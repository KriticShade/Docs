               "nmap","netcat","burpsuite","postman")

    $found = Get-Command $tool -ErrorAction SilentlyContinue

# PARTIE 1 — LA NOTE DE SERVICE / NOTE TECHNIQUE

## 1.1 Structure de la note

```
OBJET : Contrôle interne périodique de conformité SSI des postes de travail
RÉFÉRENCE : [Politique SSI] / [Charte informatique] / [PSSI]
DATE : 
DESTINATAIRES : Direction, RH, Managers, Utilisateurs concernés
CLASSIFICATION : INTERNE / RESTREINT
```

## 1.2 Contenu obligatoire de la note

### A) Le contexte et le pourquoi

```
Rédige ainsi :

"Dans le cadre de la politique de sécurité des systèmes d'information 
(PSSI) de [Organisation], et conformément à la charte informatique 
signée par chaque utilisateur, [Direction/RSSI] procède à des contrôles 
internes périodiques des postes de travail.

Ces contrôles visent à :
- Vérifier la conformité technique des configurations
- S'assurer du respect des règles d'usage définies
- Identifier les vulnérabilités et risques potentiels
- Maintenir l'intégrité et la sécurité du SI
- Protéger les données de l'organisation et des utilisateurs"
```

### B) Le cadre juridique et réglementaire — CRUCIAL

```
Mentionner obligatoirement :

✦ RGPD (Règlement UE 2016/679)
  → Licéité du traitement, information des personnes
  
✦ Code du travail - Articles L1121-1, L2323-47
  → Proportionnalité, information préalable des IRP
  
✦ Recommandations CNIL
  → Cybersurveillance sur les lieux de travail (délibération)
  
✦ Charte informatique interne signée
  → Base contractuelle du contrôle
  
✦ PSSI de l'organisation
  → Cadre politique interne
  
✦ Si secteur public : Code des relations entre 
  le public et l'administration
```

> ⚠️ **POINT CRITIQUE** : Les employés doivent avoir été **informés préalablement** que leurs postes peuvent faire l'objet de contrôles. Si ce n'est pas dans la charte → **STOP**, corrige ça avant tout contrôle.

### C) Les modalités opérationnelles

```
Préciser :

1. QUI réalise le contrôle
   → RSSI + Correspondant SSI
   → Présence possible du manager
   → Jamais seul si litige potentiel

2. QUAND
   → Planifié (contrôle périodique annuel/semestriel)
   → Ou inoppiné (sur événement de sécurité)
   → Durée estimée par poste : X heures
   
3. COMMENT
   → En présence de l'utilisateur (RECOMMANDÉ fortement)
   → Sur poste allumé avec session ouverte
   → Script automatisé + vérifications manuelles
   → Aucune modification du poste sans validation
   
4. PÉRIMÈTRE
   → Postes concernés (PC Internet / PC Restreint)
   → Ce qui est contrôlé (liste exhaustive)
   → Ce qui NE l'est PAS (vie privée stricte, 
     dossier marqué "PERSO" selon jurisprudence)
     
5. RESTITUTION
   → Rapport individuel
   → Rapport consolidé anonymisé
   → Délai de restitution
   → Procédure en cas de non-conformité détectée
```

### D) Les garanties pour l'utilisateur

```
- Droit à la contradiction
- Possibilité d'être accompagné (délégué du personnel)
- Confidentialité des résultats individuels
- Distinction claire écart/faute
- Pas de sanction automatique sur un premier écart mineur
```

### 2.2 GESTION DES COMPTES ET PRIVILÈGES — CRITIQUE POUR TES DEVS

C'est **LE point le plus sensible** avec des comptes user + admin sur le même poste.

```powershell
# Tous les comptes locaux et leur état
Get-LocalUser | Select-Object Name, Enabled, 
                               LastLogon, 
                               PasswordLastSet,
                               PasswordRequired,
                               PasswordExpires

# Membres du groupe Administrateurs local
Get-LocalGroupMember -Group "Administrators"

# Membres de tous les groupes locaux sensibles
$groups = @("Administrators","Remote Desktop Users",
            "Power Users","Backup Operators")
foreach ($g in $groups) {
    Write-Host "=== $g ===" -ForegroundColor Yellow
    Get-LocalGroupMember -Group $g -ErrorAction SilentlyContinue
}
```

**Ce que tu cherches :**
- [ ] Compte Administrateur local par défaut **désactivé ou renommé**
- [ ] Compte Invité **désactivé**
- [ ] Combien de comptes admin locaux ? (doit être maîtrisé)
- [ ] Le compte utilisateur courant est-il dans les admins ? (ne devrait pas l'être pour l'usage quotidien)
- [ ] Comptes fantômes / comptes de test oubliés

```powershell
# Politique de mot de passe locale
net accounts

# Dernières connexions par compte
Get-EventLog -LogName Security -InstanceId 4624 -Newest 100 |
Select-Object TimeGenerated, 
              @{N='User';E={$_.ReplacementStrings[5]}},
              @{N='LogonType';E={$_.ReplacementStrings[8]}},
              @{N='IP';E={$_.ReplacementStrings[18]}} |
Where-Object {$_.User -notmatch 'SYSTEM|NETWORK|LOCAL'}

□ "Comment gérez-vous vos mots de passe ?" 
  (gestionnaire ? post-it ?)
□ "Avez-vous des accès à des systèmes externes ?"
□ "Avez-vous des données professionnelles sur des 
   supports personnels ?"
□ "Avez-vous signalé des incidents/anomalies ces 
   derniers mois ?"
□ "Partagez-vous des credentials avec des collègues ?"
```

## 3.2 Contrôle des accès logiques

```
À VÉRIFIER CÔTÉ SI / ACTIVE DIRECTORY :
□ Droits AD de l'utilisateur cohérents avec sa fonction
□ Groupes AD : pas de droits résiduels (ancien poste ?)
□ Comptes de service associés à la personne
□ Accès VPN : actif ? nécessaire ?
□ Accès aux partages réseau : audit des permissions
□ Boîtes mail partagées : toujours justifiées ?
□ Droits sur applications métier : principe de moindre privilège ?

REQUÊTES AD UTILES :
# Groupes de l'utilisateur
Get-ADPrincipalGroupMembership -Identity "username" | 
Select-Object Name, GroupCategory, GroupScope

# Dernière connexion AD
Get-ADUser -Identity "username" -Properties LastLogonDate |
Select-Object Name, LastLogonDate, Enabled
```

## 4.2 Système de cotation des risques

```
GRAVITÉ × VRAISEMBLANCE = CRITICITÉ

Gravité :
1 - Négligeable
2 - Limitée
3 - Importante  
4 - Critique

Vraisemblance :
1 - Improbable
2 - Possible
3 - Vraisemblable
4 - Quasi-certaine

Score 1-4   : FAIBLE    → Surveillance
Score 5-9   : MODÉRÉ    → Action planifiée (< 3 mois)
Score 10-14 : ÉLEVÉ     → Action rapide (< 1 mois)
Score 15-16 : CRITIQUE  → Action immédiate
```

# PARTIE 5 — ASPECTS LÉGAUX ET PIÈGES À ÉVITER

## Ce que tu NE dois PAS faire

```
🚫 Extraire des mots de passe en clair
🚫 Accéder aux fichiers marqués "PERSO" sans présence de l'utilisateur
   et accord (jurisprudence Nikon - Cass. soc. 2 oct. 2001)
🚫 Lire le contenu des mails personnels
   (même sur messagerie pro si clairement identifiés comme perso)
🚫 Effectuer le contrôle à l'insu TOTAL de l'utilisateur
   sans information préalable générale
🚫 Utiliser les résultats à des fins disciplinaires 
   sans respecter la procédure RH
🚫 Conserver les données de contrôle au-delà du nécessaire
🚫 Partager les résultats individuels en dehors du circuit prévu
```

## Ce que tu DOIS faire pour te protéger

```
✅ Faire signer une feuille de présence par l'utilisateur
✅ Garder les scripts utilisés (reproductibilité)
✅ Horodater toutes les actions
✅ Travailler en binôme
✅ Documenter les écarts, même mineurs
✅ Distinguer clairement constat et qualification
   (le constat, c'est ton travail ; la sanction, c'est RH/direction)
✅ Avoir une chaîne de validation : RSSI → DRH → Direction
   avant toute suite disciplinaire
```
